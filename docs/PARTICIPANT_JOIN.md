# Participant access — 21 October 2026

`/join` starts with a presentation code and name form. A valid QR or shared `?code=` link supplies the code automatically and hides the code field, so only a name is requested. Direct visits without a code retain the code field; malformed codes can be corrected there. The action reads Katıl. Account login and participant registration remain available, and switching back preserves the code. Both paths reach the same question and activity experience. UI copy uses name/isim; the internal nickname field remains compatible with existing records and clients.

Guest participation creates a random participant identity with `guest: true`, an empty email and no password. Nicknames are normalized and limited to 2–40 characters. Code, nickname, trash state and presentation access are validated before any identity or membership is created. Nicknames are visible to the instructor and in reports. They are not credentials: two browsers using the same nickname receive separate identities and private histories.

The HttpOnly `linba_participant_session` cookie lasts up to seven days. Refreshing retains the identity, saved questions and submitted responses. Clearing cookies, changing nickname or using another browser creates a separate identity; a nickname alone cannot recover past participation. Presentation access expiry is checked independently of cookie lifetime. Unsubmitted activity drafts keep their existing page-local behavior.

Participant requests use `/api/participant/auth`, `/api/participant/join` and narrowly allowed `/api/participant/courses/:id` routes. Source-slide media uses the same participant scope. The instructor's `linba_session` cookie remains independent, so testing participation alongside an instructor workspace does not replace the instructor session or grant guest requests instructor permissions. Existing participant sessions in the main cookie remain compatible.

Validation: `npm run test:participant-join` uses an isolated temporary database. `npm run test:participant-join:integration` uses a running local server and removes only its own fixture records/files. Set `LINBA_DATA_DIR` to the server's data directory and `LINBA_TEST_URL` to its URL. It checks invalid joins, origin validation, independent same-name identities, source access, private records, activity responses, session persistence, concurrent teacher/guest cookies, account registration/login, blocked management routes and expiry. Browser QA additionally covers a guest question, submitted-answer persistence after reload, nickname changes, code retention when switching login modes, error copy and narrow/light/dark layouts.
